# Win7ExplorerRestorer

Self-contained bootstrap for Win7ExplorerRestorer: downloads the Microsoft binary (`explorer.exe`, Win7 SP1 x64) **once** from the symbol server, verifies it against a source-pinned SHA-256 hash, patches its imports to use `wrp64.dll`, and **injects UI resources generated by this project** (strings, menus, dialogs, and accelerators). Offline from the second startup.

> ## Localization v0.0.3: no `.mui` required—ever
>
> Users **do not need to obtain an `explorer.exe.mui` file**: there is no need to copy one next to the installer; the `WIN7EXPLORERESTORER_REFERENCE_MUI` variable no longer exists; there is no `.mui` identity check; and the installer does not query any symbol server for `.mui` files. The old "transplant" mechanism (v0.0.2) was removed after real-world tests (root cause documented in `localizer.h` and CI logs: `UpdateResource` rejects writes to an LN binary marked MU with `ERROR_NOT_SUPPORTED` 50; removing only the marker fails with `ERROR_INVALID_PARAMETER` 87; the only accepted approach is a complete rewrite of the resource table).
>
> The new pipeline is entirely project-generated:
>
> ```
> localization/catalog/en.json, it.json        <- OUR OWN text (project-owned, GPL)
> localization/templates/*.templates.json      <- structure (IDs, styles, rects,
>                                                 classes, commands): no MS text
>                 |
>        tools/build_resources.py              <- generates actual PE PAYLOADS
>                 |                             (STRINGTABLE/MENU/DIALOGEX/ACCEL)
>                 |                             and VALIDATES them by parsing them back
>        tools/embed_catalog.py                <- embeds into lang_catalog.h (blob)
>                 |
>        Win7ExplorerRestorer.exe               <- at install time: atomically rewrites
>                                                 the resource table in the private copy
>                                                 (copies all existing resources,
>                                                 "MUI" -> "CUI", injects blobs)
> ```
>
> - **Languages**: `en-US` (always present; fallback) and `it-IT`. An OS using another language gets en-US. To add a language, add `catalog/<id>.json`; the structure is shared.
> - **Pre-flight validation** (any failure stops the installation; the shell is never left partially localized): `tools/verify_catalog.py` (IDs, types, counts, placeholders, duplicate/missing accelerators, en↔it consistency, fallback coverage) + round-trip validation in `build_resources` (each generated payload is parsed back and compared for structure and text) + `tools/check_pe_resources.py` (checks the output file for byte-for-byte presence, successful parsing, and MUI neutralization).
> - **Error fallback**: if resource generation or injection fails, installation stops with an explicit error (exit 1) and the resource transaction is discarded. `--allow-partial-localization` no longer exists.
>
> ### Copyright / repository contents
>
> | Content | Origin | Distributed? |
> |---|---|---|
> | Installer code + Python tools | Project | Yes (GPLv3) |
> | Text in `localization/catalog/*.json` | Project | Yes |

> Structural reconstruction is not guaranteed: the template descriptor is marked `BEST-EFFORT` for window/control style bits (derived from constraints + Win32 defaults). Reconciliation against the reference file uses `analyze_mui.py --templates` + `build_resources.py --compare` (structure only, never text). See `localization/templates/…._notice`.

## Build (Windows, with Visual Studio 2022 or the v143 toolset)

```bat
python tools\embed_catalog.py
msbuild installer\Win7ExplorerRestorer\Win7ExplorerRestorer.vcxproj /p:Configuration=Release /p:Platform=x64
```

Or from an **x64 Native Tools Command Prompt**:

```bat
cd installer\Win7ExplorerRestorer
cl /std:c++17 /utf-8 /O2 /W4 /EHsc main.cpp downloader.cpp winhash.cpp importpatch.cpp localizer.cpp /link bcrypt.lib wintrust.lib crypt32.lib wininet.lib
```

`lang_catalog.h` is GENERATED; do not edit it by hand.

## Microsoft constants verified — DONE (2026-09-28)

Values confirmed by the user on Windows 10 21H2 LTSC (19044) and re-verified on every CI run (`selfcontained-ci`, step "Download reference explorer.exe and re-verify pinned identity"). To verify them manually:

```bat
curl.exe -L -o %TEMP%\explorer-ref.exe "https://msdl.microsoft.com/download/symbols/explorer.exe/4CE7A1442C0000/explorer.exe"
certutil -hashfile %TEMP%\explorer-ref.exe SHA256
python tools\analyze_mui.py %TEMP%\explorer-ref.exe --dump-headers
```

`certutil` must print one of the two allow-listed hashes (documented variants in `config.h`), and `--dump-headers` must show `TimeDateStamp 0x4CE7A144`, `SizeOfImage 0x2C0000`, machine `0x8664`, and the imports `SHLWAPI.DLL`, `OLE32.DLL`, `EXPLORERFRAME.DLL`. If any value differs, do NOT run the installer; report it.

## Usage

```bat
Win7ExplorerRestorer.exe [--app-dir "X:\Program Files\Win7ExplorerRestorer"] [--offline] [--skip-signature]
```

- First startup: download + verify + patch + rewrite the localized resources.
- Later startups (including with `--offline`): reuse `cache\explorer-*.pris` after re-verifying its hash; no network access is needed if the hash matches.

Never run this as a blocking logon action: there are overall deadlines, immediate cancellation at logoff/shutdown, and no writes outside the app folder.
